PART 1 Push SpecBridge to GitHub
ℹ️ The code is already committed locally. You just need a GitHub Personal Access Token (PAT) to push it. The terminal cannot prompt for passwords, so a PAT is required.

Step 1 — Create a GitHub Personal Access Token

1
Open GitHub → Settings
Go to github.com → click your avatar (top-right) → Settings
2
Developer settings → Personal access tokens
Scroll to the bottom of the left sidebar → Developer settings → Personal access tokens → Tokens (classic)
3
Generate new token (classic)
Click Generate new token (classic)
Note: SpecBridge hackathon push
Expiration: 30 days
Scopes: check repo (full control of private repos)
4
Copy the token immediately
GitHub shows it only once. Copy it — looks like ghp_xxxxxxxxxxxxxxxxxxxx

Step 2 — Push using the token

Open a terminal and run this command. Replace the placeholders:

# Replace YOUR_TOKEN and YOUR_USERNAME with your values
cd /home/kannan/Desktop/IBMDevDay/IBMDevDay

git remote set-url origin https://YOUR_TOKEN@github.com/evskannan/IBMDevDay.git

git push origin main
✅ After push succeeds, go to github.com/evskannan/IBMDevDay — you will see the specbridge/ folder and updated README.md.
⚠️ After pushing, reset the remote URL to remove the token from it: git remote set-url origin https://github.com/evskannan/IBMDevDay.git
PART 2 Get your watsonx.ai Project ID
ℹ️ Looking at your screen — you already have "Kannan's sandbox" as the default project. That is the project ID you need. Here is how to get the exact UUID.
1
Click "Projects" in the top navigation
From your watsonx home page, click Projects in the top menu bar
2
Click on "Kannan's sandbox"
This opens the project dashboard
3
Click "Manage" tab → look at the URL
Inside the project, click the Manage tab.
The URL will look like:
https://dataplatform.cloud.ibm.com/projects/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx/manage

That UUID in the URL is your Project ID. Copy it.
4
Alternative: Developer Access panel
On the watsonx home page, look for a "Developer access" panel or click Open Prompt Lab → inside Prompt Lab, look at the top-right → you'll see Project ID listed there.
PART 3 Generate an IBM Cloud API Key
⚠️ Critical hackathon rule: If an API key is found in a public GitHub repo, IBM deactivates the key and suspends the account. Keys go into SpecBridge's Settings UI only — never in code.
1
Open IBM Cloud IAM
Go to cloud.ibm.com
Click your profile avatar (top-right) → make sure account shows 2968214 - watsonx
Top navigation: Manage → Access (IAM)
2
API keys → Create
Left sidebar: API keys
Click Create an IBM Cloud API key
Name: specbridge-hackathon
Description: SpecBridge watsonx.ai access
3
Choose "Delete the leaked key" option
When creating the key, you may see an option about what happens if the key is leaked — select "Delete the leaked key" (this is the hackathon guide requirement).
4
Copy and save the key immediately
IBM shows the key only once. Click Download to save a local copy, or copy it to a password manager.
The key looks like: aBcDeFgHiJ1234567890_xxxxxxxxxxxxxxxxxxxx
PART 4 Understand the Models — Which Granite to Use

SpecBridge defaults to ibm/granite-13b-chat-v2. Here is what the models mean and which to pick:

Model ID Best for Speed Cost
ibm/granite-3-8b-instruct Fast generation, good quality — recommended for demos Fast Low
ibm/granite-13b-chat-v2 Good balance — SpecBridge default Medium Medium
ibm/granite-20b-multilingual Multi-language transcripts Slow Higher
ibm/granite-34b-code-instruct Code generation (use for Jython script writing) Slow Higher
🚫
These 3 models are BANNED by the hackathon — SpecBridge already blocks them in the UI:
llama-3-405b-instruct  ·  mistral-medium-2505  ·  mistral-small-3-1-24b-instruct-2503

How to browse models in watsonx.ai

1
Click "Foundation models" in the top navigation
This shows all available models. Filter by IBM to see Granite models only.
2
Click any model → copy the "Model ID"
The model ID is what you paste into SpecBridge Settings (e.g. ibm/granite-3-8b-instruct)
3
Or use "Fetch models" button in SpecBridge Settings
In SpecBridge → Settings → watsonx config → click Fetch models from endpoint — it will pull the live list and populate the dropdown automatically.
PART 5 Wire Everything into SpecBridge Settings
1
Start SpecBridge
Open a terminal: 
cd /home/kannan/Desktop/IBMDevDay/IBMDevDay/specbridge
npm run dev
Open browser: http://localhost:5173
2
Click the "Settings" tab (last tab)
You will see "Generator LLM" and "Validator LLM" cards
3
Configure Generator LLM (watsonx.ai)
Provider: IBM watsonx.ai (already selected by default)
Endpoint URL: https://us-south.ml.cloud.ibm.com (pre-filled)
Project ID: paste the UUID from Part 2
API Key: paste the IBM Cloud API key from Part 3
Model: select ibm/granite-3-8b-instruct (or click Fetch)
4
Configure Validator LLM — same values
Use the same Project ID, API key, and model for the Validator. You can use a different (lighter) model to save credits.
5
Click "Test Connection" on both
You should see: ✅ Connected — N models available
If it fails: check the Project ID is correct and the API key has no extra spaces.
PART 6 First Run — End-to-End Demo
1
Inputs tab → Load Demo
Click "Load Demo" — loads the synthetic EAGLE Utilities PM planning transcript
2
Platform: IBM Maximo Application Suite (default)
Leave platform as Maximo for the demo. Change to ServiceNow/SAP to test other platforms.
3
Generation tab → Generate All Sections
Click Generate All Sections. Watch 6 sections stream in:
Requirements → AS-IS → TO-BE → FSD → TSD → RICEF-E-001.md
The traceability % counter in the header shows evidence spans in real time.
4
Validation tab → Validate Spec
Click Validate Spec — Validator LLM scores all 5 criteria and lists any blockers.
5
Output tab → Export Handoff Bundle (.zip)
Click Export Handoff Bundle (.zip). Open the ZIP — find 05-ricef/RICEF-E-001.md. This is the file Bob uses in Milestone 2.
🎉
Milestone 1 complete! You now have a machine-buildable RICEF-E-001.md.
For Milestone 2: paste that file into a fresh Bob task with the Maximo API URL + key → Bob deploys the Jython script automatically.
